## Keputusan pengguna dan implementasi

Dua jawaban AskUserQuestion menetapkan semua ekspor melalui worker yang ada
serta kolom identitas lengkap dengan finansial sesuai izin. Keputusan masuk
[M-04](../../PRD/02-modules/m04-assets.md); desain penyimpanan dan P-15 diturunkan
ke SDD/UX. Skala gabungan L karena kontrak API, policy/data sumber, adaptor
worker, empat route, antarmuka dan pengujian perlu melayani satu alur utuh;
infrastruktur worker/retensi/renderer tidak diduplikasi.

- GET /assets/export menerima format XLSX/PDF, q/sort/filter katalog dan
  Idempotency-Key UUIDv4, lalu mengembalikan 202 dengan job. Header wajib kini
  dinyatakan OpenAPI untuk route idempoten. Parameter halaman atau tak dikenal
  ditolak; pengiriman ulang terikat pemohon/endpoint/filter.
- GET /assets/exports, /assets/exports/{id} dan /download menyajikan riwayat,
  status serta URL privat hanya pekerjaan katalog milik pemanggil. Route
  terdaftar sebelum /assets/:id dan semuanya mendeklarasikan asset.export.
- Izin asset.view/asset.export dibaca ulang dari SQL. Scope own memakai
  penanggung jawab, restricted memakai kelayakan siswa, scope tanpa aturan
  ditolak. Tidak menuntut report.view/report.export. Filter hasil impor tetap
  hanya milik pengunggah; aset dihapuskan tidak masuk ekspor katalog.
- M-04 memakai predicate/filter/urutan katalog yang sama dan membuka sumber
  melalui index publik. Query dibatasi limit+1 untuk mendeteksi overflow.
  Sumber/nilai tidak di-SELECT bila izin finansial tidak mencakup seluruh baris;
  financial own hanya jika dataset sudah own. R-07 tidak mendapat finansial.
- Kolom mencakup kode/nama/merek/model/nomor seri, kategori/gedung/ruangan,
  kondisi/status, tahun, kelayakan pinjam/siswa, penanggung jawab dan QR
  terpasang; sumber/nilai opsional. Foto/dokumen/riwayat/biaya tidak dimuat.
- Worker M-16 yang ada membaca data saat pemrosesan, membuat XLSX/PDF dan
  menyimpan file privat. ASSET_EXPORT_REQUESTED atomik dengan job/outbox;
  ASSET_EXPORTED, file SIAP dan ExportReady commit bersama. NT-42 menuju
  /aset?ekspor={id}. Tidak menambah dependency, job type atau owner_type baru.
- Batas existing XLSX 100.000/PDF 5.000, overflow gagal tanpa file terpotong.
  Nama sekolah wajib untuk PDF; kop/filter/waktu WIB/pencetak tersedia.
  Nomor seri/formula sebagai teks dan DECIMAL presisi tetap dipertahankan.
- File berlaku 24 jam dan URL maksimal lima menit. Hash hak/role dan membership
  scoped diperiksa saat worker/publikasi/status/unduh; perubahan membatalkan
  akses file lama. Kompensasi PUT gagal dan cleanup memakai jalur yang ada.
- P-15 mengirim seluruh filter URL tanpa page/per_page, menampilkan format,
  status/riwayat dan unduh. Pengiriman tak pasti mempertahankan kunci/filter
  awal. Deep link membuka status tanpa mengajukan job. Cache dipisah akun/izin.

dari sesi retensi/pseudonimisasi: AdminTargetRow (cli.repository), PermintaanTampil
dan PenggunaSasaran (password-reset.repository), KredensialRow (profile.repository)
masih string wajib. Run berikutnya juga menangkap keterangan opsional yang
dikirim sebagai undefined pada pseudonymization.service. Tidak ada diagnostik

entrypoint masih berubah saat lint diperiksa; perbaikan alur akun tetap milik
sesi tersebut, dirinci di handoff. Ini tetap menahan gerbang build/CI gabungan.

bigint setelah kegagalan fresh migration menghalangi kedua suite. Tidak ada
DDL/migration baru dari fitur ekspor. Pemilik retensi perlu meninjau koreksi
tersebut bersama pengujian alurnya.

cleanup pembaca PDF harus memakai loadingTask.destroy, dan adapter web memberi

Pemeriksaan 320px menemukan pencarian/pagination P-15 melebar; keduanya kini
membungkus baris tanpa mengubah filter atau navigasi. Review arsitek, integrasi
BullMQ/storage/notifikasi nyata, pengujian beban dan QA staging tetap diperlukan.
