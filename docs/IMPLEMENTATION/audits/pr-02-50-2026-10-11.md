# PR-02-50 — drill-down dashboard dan render responsif

Implementasi lokal, 11 Oktober 2026. Cakupan mengikuti jawaban pengguna: lengkapi tujuan yang sudah tersedia; tujuan yang belum tersedia menjadi dependensi. Belum dibuat PR remote atau merge.

## Perilaku

- Judul KPI menjadi tautan ke daftar sumber; kartu lain menggunakan aksi Lihat. Klik biasa memakai router aplikasi, modifier tetap menggunakan anchor native.
- Pengguna aktif/distribusi role menuju `/pengguna?status=AKTIF`. Distribusi role membuka keseluruhan pengguna aktif; data kartu belum menyediakan ID role untuk menyaring tiap segmen.
- Total/ringkasan aset menuju katalog aktif. Rincian kondisi/status memiliki tautan per enum menuju katalog dengan filter yang diteruskan sampai API.
- Aset tanpa label QR menuju `/label-qr?belum=true`; API katalog menyaring `filter[qr_terpasang]=false` dengan scope dan pengecualian aset dihapuskan yang sama. Daftar langsung dimuat, paginasi 25, pilihan lintas halaman dipertahankan.
- Hak akses tujuan diperiksa selain hak akses kartu. Tidak muncul tautan ke halaman yang belum terdaftar atau parameter path yang belum terisi; konfigurasi memakai tujuan pertama yang tersedia dan diizinkan.
- Grid menggunakan token desain: 1 kolom di ponsel, 2 mulai 768px, 3 mulai 1366px. Zona kecenderungan diciutkan di ponsel dan dapat dibuka melalui keyboard.

## Validasi

- Uji aplikasi melewati router dan adapter HTTP produksi: klik pengguna aktif, QR, kondisi, status; izin tujuan, dependensi belum tersedia, fallback konfigurasi; axe pada grafik dan tautannya.
- Uji API memeriksa parsing boolean false, penolakan nilai tidak valid, dan SQL filter QR yang mempertahankan scope restricted serta aset aktif.
- Hasil: 38/38 uji web (dashboard-drilldown, alur, QR) dan 2/2 uji API filter QR lulus. Axe menggunakan helper WCAG 2.1 A/AA; kontras warna tidak diukur oleh JSDOM.
- Build produksi, typecheck, lint kode aplikasi/script, dan pemeriksaan batas impor.
- `node scripts/qa/dashboard-browser.mjs` setelah build: Chrome headless dengan context baru per viewport dan latensi fixture API 80ms/request. Ringkasan dihitung dari 5.000 aset sintetis. Semua lima kartu dimuat sebelum pencatatan waktu dan dua animation frame ditunggu.

| Lebar | Render awal (ms) | Kolom | Overflow | Zona kecenderungan |
|---|---:|---:|---|---|
| 320 | 874 | 1 | Tidak | Diciutkan; Enter membuka |
| 768 | 818 | 2 | Tidak | Terbuka |
| 1024 | 829 | 2 | Tidak | Terbuka |
| 1440 | 828 | 3 | Tidak | Terbuka |

Angka di atas hanya menguji browser produksi dengan fixture; bukan waktu agregasi/API/database nyata. `DATABASE_URL` tidak tersedia. Acceptance FR-15.1 end-to-end ≤3 detik pada database 5.000 aset tetap perlu pengukuran di staging. Fixture ini juga tidak mengklaim cakupan visual semua templat role.

Lint global `npm run lint` turut membaca worktree `.kilo/worktrees/good-bubble/wireframe` dan gagal pada berkas di sana; pemeriksaan kode aktif dilakukan terpisah tanpa mengubah worktree tersebut.

## Dependensi tujuan

- P-67 permintaan reset password serta P-73/P-74 Activity Log belum memiliki halaman web terdaftar. Kartu tetap menampilkan data, tanpa tautan mati. Implementasi halaman tersebut berada di luar cakupan yang disetujui.
- Pengajuan Saya mempertahankan tujuan P-30 `?saya=true` yang ditetapkan manifes. Daftar reservasi tidak mewakili seluruh jenis pengajuan approval ataupun rentang tanggal pengajuan; tidak ditambahkan filter tanggal reservasi yang berbeda semantik. Penyamaan sumber/tujuan seluruh tipe pengajuan merupakan dependensi kontrak dashboard.
