## Hasil implementasi

M-09 menyediakan pemeriksa pinjaman dan kewajiban tanpa ambang nominal blokir
reservasi. Nomor pinjaman/ID denda ditampilkan pada penolakan. Composition root
API dan worker masing-masing memasang pemeriksa secara idempoten. UserService
dan GraduationService mengunci akun serta memakai pemeriksa yang sama.
Kelulusan hanya memilih R-07 dan memeriksa ulang role/status setelah terkunci.
Check-out mengunci baris peminjam yang sama, sehingga akun tidak dapat dinonaktifkan
di antara pemeriksaan status dan pembuatan pinjaman.

POST /users/{id}/pseudonymize memakai user.update, tetap melalui autentikasi/2FA
normal. Service mewajibkan R-01/all, bukan diri sendiri, memeriksa izin aktual dari
SQL, akun NONAKTIF dan seluruh kewajiban. Body ketat berisi alasan, referensi
permintaan dan metode verifikasi yang sudah ada. Permintaan ulang mengembalikan
waktu operasi pertama tanpa audit ganda. UI P-63 menyediakan penjelasan, isian,
pernyataan memahami dampak dan konfirmasi modal sebelum POST.

Identitas users diganti penanda, nip_nis/telepon/unit kerja/teks unit lama menjadi
NULL, dan password diganti penanda tidak dapat digunakan. Secret/kode 2FA,
password_history dan device token dibuang; refresh token dicabut. Password reset
terbit kedaluwarsa; permintaan menunggu ditolak dengan penanda privacy_revoked_at.
Pelaku otomatis tetap NULL/SYSTEM, tanpa memalsukan ID pengguna. USER_PSEUDONYMIZED
ditulis dalam transaksi yang sama tanpa menyalin identitas/hash lama.

Trigger database menolak pemulihan/perubahan akun yang sudah diproses, termasuk
jalur tulis lama. Guard service memberikan galat bisnis; UI menyembunyikan
ubah/aktifkan/pemulihan dan menolak pembukaan form lewat deep link. Pembukaan
ulang denda mengunci peminjam dan menolak akun yang sudah diproses; opsi aksi
detail denda juga tidak ditawarkan. Login/refresh dan penguncian penghitung gagal
mengecualikan akun permanen, sehingga login ditolak seragam dengan 401 dan tidak
mencoba memutasi akun. Riwayat pinjaman tetap terbaca melalui relasi ID yang sama.

Job personal-data-retention berjalan 01:10 WIB (18:10 UTC), melalui wrapper
SYSTEM/JOB-05. Kandidat siswa dipaginasi per ID, diperiksa ulang dalam transaksi
per akun; pengguna berkewajiban yang dilewati tidak menghalangi kandidat berikutnya.
Cleanup laporan impor memakai batch 200/SKIP LOCKED per pemilik modul, audit
USER_IMPORT_REPORT_PURGED/ASSET_IMPORT_REPORT_PURGED, dan penanda selesai agar
idempoten. Job berjalan tidak dipurge. API mengembalikan report_expires_at dan
report_expired, menyembunyikan rincian/nama sesudah tenggat sebelum cleanup.
UI P-62/P-17 menutup rincian/unduhan/koreksi, termasuk dengan timer pada tab yang
dibiarkan terbuka; status dan hitungan tetap tersedia.

Migration **0072_user_pseudonymization.sql** menambah deactivated_at,
pseudonymized_at, report_purged_at, privacy_revoked_at, indeks retensi dan guard
identitas. NIP/NIS NULL hanya sah sesudah pseudonimisasi. Jangkar akun lama
dibuktikan dari keputusan status sukses terakhir, bukan waktu sunting profil.
Terminal impor tanpa waktu selesai memakai waktu migration secara konservatif.
Down migration ditolak jika sudah ada akun dipseudonimkan: identitas tidak
disimpan untuk operasi balik. Tidak ada migration pada database aplikasi.

## Serah terima dan batas

- Review arsitektur/keamanan, CI dan staging tetap terbuka. Status In Progress
  tidak menyatakan milestone atau keseluruhan Phase 01/05 selesai.
- Migration harus mendahului deployment API/worker yang membaca kolom baru.
  Job otomatis dapat memproses akun lama yang memenuhi retensi berdasarkan
  audit; pastikan bukti/tanggal penonaktifan sekolah ditinjau sebelum aktivasi
  lingkungan produksi. Pengujian di sini hanya memakai data terisolasi.
- Pseudonimisasi mengganti identitas users. Audit historis, snapshot transaksi
  dan foto dapat tetap mengandung identitas sesuai keputusan produk; bukan
  penghapusan menyeluruh dari seluruh bukti atau cadangan.
- Tidak ada manipulasi objek/media produksi; pengujian membuktikan metadata foto
  tetap, bukan menjalankan layanan bucket nyata. Salinan laporan yang sudah
  diunduh berada di luar lifecycle server.
- [Runbook](../runbooks/permintaan-privasi.md) menetapkan register/verifikasi
  permintaan sekolah dan respons maksimum 3×24 jam. Tidak menambah mesin
  permohonan/approval baru. Jalur tulis pengguna berikutnya harus menghindari
  akun permanen; trigger menjadi penjaga terakhir.
