## Cakupan dan keputusan

Batch dua PR mengikuti permintaan eksplisit pengguna. PR-01-26 menambah bukti penerimaan PM-05 tanpa mengubah logika otorisasi produksi. PR-03-36 mengisi CD-07 pada script deploy yang sudah ada. Skalanya dikoreksi S/S menjadi M/M karena lima alur, upload foto, pemulihan balasan hilang dan pembersihan memerlukan driver Python standar serta pengujian kegagalan yang utuh; tidak menambah dependency atau endpoint.

Tiga jawaban AskUserQuestion menetapkan fixture staging khusus, kegagalan penuh bila konfigurasi belum lengkap, dan penutupan tiket dengan Perbaikan Ringan tanpa perubahan kondisi. Keputusan menjadi bagian [CD-07](../../PRD/03-architecture/deployment-ops.md), diturunkan ke [SDD-16](../../SDD/16-infrastructure-deployment.md) dan [runbook](../runbooks/smoke-test.md).

- Login produksi menerbitkan cookie WEB/Bearer ANDROID. Dua instance API berbagi PostgreSQL/Redis dan kunci Ed25519 uji. Perubahan matriks, scope, role dan status dilakukan lewat HTTP administrasi dengan login produksi tersendiri.
- Sesi target tidak diganti, di-refresh atau login ulang. Cache lama tetap ada dengan TTL positif, waktu FixedClock tidak dimajukan. Versi role awal sama-sama 1. Permintaan berikutnya pada instance lain langsung mengikuti hak baru. Mandatory OTP dan logout juga diperiksa.
- Tidak ada authPalsu, setAuthContext, middleware pengganti, penghapusan cache atau sleep TTL pada berkas bukti PM-05. Helper auth dipakai hanya untuk kunci Ed25519 sementara dan layanan dua faktor produksi.
- Smoke memeriksa kesehatan/header/404 sebelum login, pencarian aset sesuai fixture, resolusi QR UUID, preview/pengajuan reservasi idempoten, presign/PUT/confirm foto dan pembuatan tiket. Default penuh; health-only harus eksplisit.
- Kredensial hanya environment secret. Token di memori, tidak masuk argumen/artefak atau unggahan storage. HTTPS diverifikasi, redirect ditolak; HTTP loopback hanya opt-in lokal. Role akun, scope, kalender dan approver fixture harus dikonfigurasi operator.
- Marker UUID per run membatasi pemulihan ID setelah balasan POST hilang. Tidak ada retry transaksi otomatis. Cleanup menutup tiket tanpa kondisi_aset, membatalkan reservasi dan logout; kegagalan tetap membuat exit nonzero. Tiket/foto/audit dipertahankan, slot dilepas melalui API bisnis.
- Workflow staging memakai secrets/variables khusus dan --full. Filter CI kini meliputi deploy/staging agar perubahan script saja juga menguji API. Kontrak Python dijalankan job uji berkas; alur nyata masuk suite integrasi.

Total **65 uji unik** lulus: delapan integration JWT, enam integration smoke (termasuk dua run sukses pada fixture yang sama), 44 regresi unit authenticate/middleware/cookie dan tujuh kontrak Python. Smoke memeriksa status DIBATALKAN/SELESAI, slot RELEASED, foto terkonfirmasi/tertaut, audit DAMAGE_VERIFIED tetap ada, kondisi aset BAIK tidak berubah dan tidak ada sesi aktif sesudah cleanup. Kontrak menguji URL/redirect, header storage, PNG valid dan cleanup yang tetap lanjut saat penutupan gagal atau respons rusak.

Root TypeScript build, typecheck API tests, lint kedua berkas integrasi, bash -n, 14 pemeriksaan batas impor, audit_docs.py dan validate_impl.py lulus. Tidak mengukur ulang coverage seluruh monorepo karena produksi otorisasi tidak berubah; gerbang CD-02 tetap milik CI penuh.

Harness diperbaiki mengikuti skema/katalog/konfigurasi yang ada; validasi produksi tidak dilonggarkan. Ambang denda hanya diisi pada database uji dan nilai awal dipulihkan saat teardown. Akun Petugas/approver uji dinonaktifkan saat teardown agar tidak menjadi penerima/approver aktif suite berikutnya. Prasyarat operasional ini dicatat pada runbook. Tidak ada migration baru.

Pengujian smoke lokal memakai API/JWT/database/cache nyata dengan adapter object storage HTTP di memori dan header HSTS tiruan. Ini tidak membuktikan DNS/TLS/Nginx, bucket S3, AV worker, secrets environment, atau deployment staging. Eksekusi runner terhadap staging nyata beserta review/CI merupakan pekerjaan lingkungan yang masih terbuka; pemeriksaan kesehatan saja tidak menutup CD-07.
