# PR-02-40 + PR-02-41 + PR-02-42

Implementasi lokal 12 Oktober 2026, belum ada PR remote/merge. Perubahan lokal yang sudah ada dipertahankan.

## Kontrak dan perilaku

- PR-02-40: `GET /auth/2fa/status` (Bearer, gerbang 2FA tetap berlaku), selalu akun pemanggil. Satu kueri/snapshot membaca waktu aktivasi dan menghitung kode belum terpakai; disabled → sisa 0, tidak menampilkan peringatan. Aktif dengan ≤2 kode → peringatan. Hanya empat field kontrak PRD M-01 §7; tidak membaca secret/hash dan tidak mengembalikan nilai kode. `Cache-Control: no-store`; endpoint terdaftar pada registri/OpenAPI.
- PR-02-41: `must_change_password` hanya meloloskan delapan POST yang ditetapkan PRD M-01 §7. GET/metode lain, route baru di bawah `/auth/`, trailing slash dan suffix tidak diloloskan. Enroll/confirm tetap masuk daftar untuk mencegah kebuntuan role wajib 2FA sebelum password diganti; middleware 2FA tidak dilonggarkan. `/me`, sesi, status/regenerasi 2FA, forgot, antrean dan reset administratif diblokir. PRD dan kedua SDD diselaraskan, menutup keputusan 43 log Phase 02.
- Reset administratif sudah menghapus locked_until, failed_login_count dan failed_login_window_start di UPDATE password yang sama sebelum pekerjaan ini; tidak ditulis ulang. Uji SQL baru membuktikan ketiga field, bersama must_change_password=true. Acceptance PostgreSQL yang sudah ada pada `auth-password-reset.test.ts` mencakup kunci dibuka serta sesi lama dicabut.
- PR-02-42: P-04 `/lupa-password` publik dengan pesan netral; P-67 `/permintaan-reset-password` berizin user.reset_password dengan filter/status/paginasi URL, verifikasi identitas wajib, penolakan beralasan, password sementara tampil sekali di state komponen. Hanya respons penerbitan yang membawa password; daftar/query cache/URL tidak menyimpannya.
- P-76 `/profil`: nama/telepon/foto sendiri, email dan role tidak menjadi isian. Foto JPG/PNG ≤2 MiB: presign USER_PHOTO → PUT tanpa cookie/header sesi → confirm SHA-256 → PUT /me. Foto pending diperiksa ulang 5 detik; signed URL tampil hanya bila server menyatakan CLEAN. Hapus foto dikirim sebagai null. Retry penyimpanan profil dapat memakai file_id yang sudah terunggah.
- P-77 `/profil/keamanan`: ganti password dengan konfirmasi/indikator aturan dan validasi server; sesi lain dicabut, perangkat ini tetap masuk. Status/kode menipis, konfirmasi regenerasi, seluruh kode lama diganti; kode baru hanya state layar dan dihapus setelah pengguna menyatakan sudah menyimpan. Tidak ada aksi menonaktifkan 2FA sendiri untuk role mana pun. Role opsional dapat memulai enrollment tanpa kode Administrator; mandatory tetap memakai kode aktivasi.
- P-79 adalah anchor `#perangkat` pada P-77: daftar sesi per platform, perangkat saat ini, IP/user-agent/waktu, konfirmasi cabut satu/semua. Cabut perangkat ini/semua menuju Login lalu mengosongkan cache (menghindari shell membaca sesi yang sudah dihapus). Topbar menautkan Profil/Keamanan/Perangkat dan meminta konfirmasi logout-all; kegagalan selain 401 tetap di dialog. P-67 kini dapat dicapai dari dashboard sesuai izin.

## Validasi dan batas

- Backend: 426 uji terkait lulus (status, hitungan/scope sendiri, gerbang positif/negatif per metode/path, SQL membuka kunci; HTTP autentikasi, registri, OpenAPI, SEC-T-01).
- Uji aplikasi melintasi router/gerbang sesi/adapter HTTP produksi: forgot netral, profil tanpa perubahan email/role, foto invalid dan unggah storage, konfirmasi password, kode sekali tampil tanpa cache, cabut perangkat/semua, izin antrean, penerbitan dengan metode wajib, penolakan gagal tetap di dialog, dan enrollment opsional. Axe pada forgot/profil/keamanan/antrean; kontras warna tidak diukur JSDOM.
- Suite web akun, registri navigasi, alur masuk, shell dan drill-down dashboard: **80/80 lulus**; termasuk 12 uji akun baru.
- Typecheck, build web produksi, lint kode aktif (akar mengabaikan worktree `.kilo/**` yang punya masalah wireframe), serta pemeriksaan batas impor.
- `node scripts/qa/account-browser.mjs` setelah build: Chrome headless, 320/768/1024/1440px. Kelima halaman, unggah foto dengan File/crypto/fetch browser, modal regenerasi, perangkat, penerbitan/penutupan password sekali tampil: tanpa overflow atau pageerror. API/storage menggunakan fixture, bukan bukti layanan nyata. `--screenshots` menghasilkan screenshot ponsel berisi data fixture untuk inspeksi.
- Screenshot P-67 pada 320px ditinjau secara visual; artefak sementara dibersihkan setelah inspeksi.
- `auth-two-factor.test.ts` ditambah acceptance GET status, no-store, parameter user_id tidak mengubah pemilik, dan kode terpakai tidak dihitung. Dua suite integrasi status/reset terkoleksi, **79 tes dilewati** karena DATABASE_URL/lingkungan layanan tidak tersedia. Verifikasi PostgreSQL/Redis dan penyimpanan/AV nyata masih harus dilakukan di lingkungan layanan.

Tidak ada migration atau pekerjaan notifikasi baru. Halaman P-07 pemberitahuan privasi di luar cakupan PR ini; halaman notifikasi hanya ditautkan jika pemanggil memiliki permission-nya.
